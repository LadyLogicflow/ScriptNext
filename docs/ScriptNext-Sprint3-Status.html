3. Etappe 3a — SharePoint-Anbindung

LIVE Microsoft-Graph-Anbindung mit Device-Code-Flow

Endpoints: POST /sharepoint/verbindung · GET /sharepoint/verbindung/status · GET /sharepoint/ordner · POST /sharepoint/import

Flow: Client startet Device-Code, User authentifiziert bei microsoft.com/devicelogin, Client pollt Status (5s), gespeicherter Refresh-Token wird verschlüsselt in DB abgelegt (pro Tenant).

Frontend: Login-Screen mit großem User-Code, Ordner-Picker (Sites → Drives → Baum), Import-Fortschritt.

Env-Vars nötig (Azure App-Registrierung): SCRIPTNEXT_SHAREPOINT_CLIENT_ID (Pflicht), SCRIPTNEXT_SHAREPOINT_AUTHORITY, SCRIPTNEXT_SHAREPOINT_TOKEN_KEY.

4. Etappe 3b — Rechtsquellen-DB & Zitier-Guard

LIVE Verifizierte Rechtsquellen aus offiziellen Feeds

Quellen: Gesetze-im-Internet (XML), BFH-Datenbank, BMF-Schreiben. Import idempotent (Unique externe_id).

Endpoints: POST /rechtsquellen/import · GET /rechtsquellen mit Filter (typ, Volltext) · GET /rechtsquellen/{id}

Zitier-Guard scharf: KI-Prompt lehnt Zitat ohne DB-Treffer ab — schreibt „Quelle offen" statt zu halluzinieren.

Frontend: Rechtsquellen-Übersicht mit Filter-Buttons, Debounce-Suche, Detail-Modal.

Doku: docs/Rechtsquellen-Schema.html

5. Etappe 3c — Feedback-Schleife & Themen-Versionierung

LIVE Rückkopplung von Trainern + Warnhinweis bei veralteter Rechtslage

Endpoints: POST /seminare/{id}/feedback · GET /seminare/{id}/feedback · GET /chunks/veraltet

Feedback: 3 Bewertungen (gut / zu_langweilig / falsche_ebene) + optionaler Kommentar. Aggregat fließt in Didaktik-KI-Prompt der nächsten Seminar-Generierung.

Versionierung: Chunks tragen quelldatum + rechtslage_gueltig_ab. Automatische Veraltet-Erkennung (365 Tage). UI zeigt Warnbadge in Themen-Karten mit Detail-Modal.

Frontend: Wiederverwendbare FeedbackWidget-Komponente + Chunk-Warnbadge im Themen-Screen.

Doku: docs/Themen-Versionierung.html

6. Etappe 3d — Multi-User & Rate-Limiting

LIVE Backend / OFFEN Frontend — Nutzer-Verwaltung, Rollen, API-Härtung

Backend (2bef3d0):

  • GET/POST/PATCH/DELETE /admin/nutzer (Admin only, via admin_erforderlich-Dependency)
  • Drei Rollen: admin (alles), editor (Upload/Generierung/Feedback), viewer (nur lesen)
  • Rate-Limiting mit slowapi: KI 10/min, Import 5/min, Auth 20/min — pro Tenant+User (Auth pro IP für Brute-Force-Schutz)
  • Admin-Bootstrap via SCRIPTNEXT_ADMIN_EMAIL + SCRIPTNEXT_ADMIN_PASSWORT beim ersten Start
  • Rolle im JWT-Payload → Frontend kennt Berechtigungen ohne Extra-Roundtrip
  • 19 Tests grün

Frontend (offen): User-Verwaltungs-UI (Nutzer-Liste, Anlegen-Modal, Rollen-Dropdown, Deaktivieren mit Bestätigung). Nur sichtbar für admin-Rolle. Kommt in Webys nächster frischer Session.
