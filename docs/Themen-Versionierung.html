Themen-Versionierung & Feedback

Wie ScriptNext veraltete Inhalte erkennt, warnt und die KI lernt

1. Warum Versionierung?

Das Problem: alternde Steuer-Inhalte

Steuerrecht ändert sich laufend. Ein Skript, das 2023 auf einem älteren §-Stand basiert, ist 2026 möglicherweise veraltet — mit Aktenzeichen, Freibeträgen oder Verfahrenswegen, die inzwischen anders sind. Wenn eine Beratungsstelle daraus ein Seminar generiert, kann das im schlimmsten Fall zu Falschinformationen führen.

Lösung: Jeder Chunk (Wissens-Baustein) trägt Versions-Metadaten. Das UI zeigt einen Warnbadge, wenn die Quelle veraltet ist. Die KI weiß Bescheid und kann proaktiv „bitte aktualisieren" vorschlagen.

2. Versions-Metadaten pro Chunk

FeldTypBedeutung
quelldatumDateDatum der Quelle (PDF-Metadaten, sonst Import-Zeitpunkt).
rechtslage_gueltig_abDate (optional)Datum, ab dem die im Chunk beschriebene Rechtslage gilt. Kommt aus dem KI-Erkennungslauf beim Chunking.
ist_veraltetbool (computed)Automatisch: rechtslage_gueltig_ab + 365 Tage < heute. Wird als Warnhinweis-Kriterium genutzt.

3. Ablauf: vom Import zum Warnhinweis

  1. Import — PDF wird hochgeladen (Web-UI) oder aus SharePoint gezogen. Metadaten (Erstellungsdatum, Titel) werden ausgelesen.
  2. Chunking — Text wird in Themen-Chunks zerlegt. Für jeden Chunk läuft eine kurze KI-Analyse: „Wann gilt die hier beschriebene Rechtslage frühestens?" → befüllt rechtslage_gueltig_ab.
  3. Speicherung — Chunks landen mit Versions-Metadaten in der DB, samt pgvector-Embedding.
  4. Nutzung — Bei jeder Seminar-Generierung werden Chunks abgerufen. Die Themen-Übersicht zeigt Gesetzeslage geändert am DD.MM.YYYY bei veralteten Chunks.
  5. Update-Hinweis — GET /api/v1/chunks/veraltet liefert dem Admin eine Liste mit Vorschlag „neu einlesen aus SharePoint oder Upload".

4. Feedback-Schleife

Nach jedem generierten Seminar kann der Trainer eine Bewertung abgeben. Das ist der zweite Lernmechanismus (neben Versionierung):

Feedback-Optionen

  • gut — Seminar passt.
  • zu langweilig — didaktisch zu monoton, zu textlastig.
  • falsche Ebene — Sprachniveau oder Vorwissen falsch getroffen.

Optional kann ein Freitext-Kommentar (max. 1000 Zeichen) mitgegeben werden.

Wie die KI daraus lernt

Feedback wird pro Zielgruppe aggregiert. Bei einer Neu-Generierung für die gleiche Zielgruppe wird das Aggregat als Zusatz-Signal in den Didaktik-KI-Prompt gegeben:

Zielgruppe: Steuer-Anfänger (Beratungsstelle)
Letzte 12 Feedback-Runden: 8× gut, 2× zu_langweilig, 2× falsche_ebene
Regel: bei „zu langweilig" mehr Beispiele/Übungen einbauen.
       bei „falsche Ebene" Sprachniveau eine Stufe einfacher.

So passt sich die KI über Zeit an, ohne dass ein Mensch Prompts manuell tunen muss.

5. API-Endpoints (Sprint 3c)

POST /api/v1/seminare/{id}/feedback
     Body:     { bewertung, kommentar? }
     Response: { id, gespeichert_am }

GET  /api/v1/seminare/{id}/feedback
     Response: { gesamt, gut, zu_langweilig, falsche_ebene, letztes_feedback }

GET  /api/v1/chunks/veraltet
     Response: { items: [...], total }

6. UI-Darstellung

Warnbadge im Themen-Screen

⚠️ VERALTET Beispiel: „Kindergeld-Berechnung 2022"

Chunk basiert auf Skript vom 12.03.2022. Rechtslage möglicherweise durch Neufassung 2024 überholt. → Empfehlung: Thema neu einlesen aus SharePoint oder Upload.

Feedback-Widget nach Seminar-Vorschau

Drei große Buttons unter der Seminar-Vorschau, optionales Textfeld darunter. Ein Klick schließt das Widget und zeigt „Danke für die Rückmeldung! Wir lernen daraus." — Feedback ist anonym pro Trainer, aber pro tenant_id+seminar_id aggregiert.

7. Datenschutz

  • Feedback enthält keine personenbezogenen Daten (keine Trainer-ID gespeichert, nur tenant_id).
  • Kommentare werden geloggt und dürfen keine personenbezogenen Daten enthalten — das UI-Widget zeigt einen Hinweis „Bitte keine Namen oder Adressen im Kommentar".
  • Chunk-Warnhinweise sind rein technisch (Datumsangaben), unproblematisch.
